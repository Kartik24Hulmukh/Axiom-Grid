# Infrastructure adversarial review — Storytold → Axiom

**Decision: patterns only for the current Axiom preview; no direct launcher, provider-platform, or ArtCraft-X integration.** A future tiny non-network utility dependency could be evaluated separately, but this review does not approve one. The blockers are trust/authority expansion, not evidence of malicious intent.

## Evidence and boundaries

Static public-source sampling on 2026-10-28 UTC. Used the supplied org-repos.json, the approved read-only helper, untruncated recursive trees for the four repositories, and pinned raw source. Also retrieved six text files at the launcher's actual craft-libs dependency revision; did not equate dependency code with library HEAD. Read Axiom's existing published worktree and policy documents. The only executed helper was the expressly supplied public-source fetcher; local review scripts only read/fetch/write research text. No Axiom files were modified. ## Top blockers and opportunities

### 1. Updater: real defenses, but a different trust root and privileged effect surface

**Observed:** launcher app installs refuse missing checksums, verify the selected artifact's SHA-256, bind advertised version to recognizable asset/tag identity, and include downgrade/running-process and staged-install protections. Feed conversion filters assets to the expected GitHub release prefix or configured mirror; it is not simply an arbitrary-URL installer. macOS validates a configured Developer ID team and bundle version. Do not describe it as having “no verification.” [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/crates/native/src/install.rs] [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/crates/core/src/feed.rs#L183-L225]

**Critical nuance:** launcher self-update delegates to craft-update at **`92d392cff132eaf53e13afff77f38b5c11b73aa0`**, whereas reviewed craft-libs HEAD is different. The actual dependency also checks published hashes and version binding. Its Windows self-update verifies Authenticode and compares publisher **subject names** against the running signed executable; that is not an independently provisioned certificate/public-key pin. Its macOS team expectation is Craft-specific, not Axiom's. [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/Cargo.toml] [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/crates/native/src/self_update.rs] [^https://github.com/storytold/craft-libs/blob/92d392cff132eaf53e13afff77f38b5c11b73aa0/crates/update/src/install.rs] [^https://github.com/storytold/craft-libs/blob/92d392cff132eaf53e13afff77f38b5c11b73aa0/crates/update/src/self_update.rs#L715-L724]

**Risk/inference:** a hash supplied by the same mutable release/feed authority detects byte corruption but is not independent release authorization. The sampled flow does not establish a uniform signed, expiring, rollback-resistant metadata root across platforms. This matters most on paths without the extra macOS/Windows signer gates. Installers deliberately invoke OS tools/package managers and can request polkit elevation; self-update replaces/relaunches executable code. That authority must not enter Axiom's read-only preview process. Launcher HTTP also uses proxy/redirect behavior unlike Axiom's fixed-loopback/no-proxy/no-redirect inference path. [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/crates/native/src/install.rs] [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/crates/native/src/http.rs] [^https://github.com/Kartik24Hulmukh/Axiom-Grid/blob/704fb45fd3c521346b86a4bf66ba68e529191ce6/docs/MODEL_IDENTITY_POLICY.md]

**Opportunity:** borrow fail-closed missing-hash behavior, staged replacement/rollback, explicit cancellation phases, version/asset binding, and symlink-aware validation as design inputs. Any Axiom updater needs a separate privileged boundary, independently approved signer/artifact manifest, anti-rollback policy including first-install floor, explicit user approval, and platform-specific qualification. Do not inherit Craft release URLs, signer IDs, or helper invocation conventions.

### 2. “Plugin API” is declarations plus trusted adapters, not a safe arbitrary-code plugin host

**Observed:** the AI platform explicitly distinguishes tool declarations from installed executable adapters. Missing adapters are refused rather than silently substituted. EngineRegistry is an in-process `Arc<dyn ModelRunner>` collection; registering the same engine/model replaces the earlier runner. EngineProvider loads weights via the runner and executes native Rust in-process, with cancellation checks, queue limits and panic conversion. These are useful lifecycle mechanisms, **not** a sandbox or attestation boundary. [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/docs/PLATFORM-CONTRACT.md] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-engine/src/registry.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-engine/src/provider.rs]

**Risk:** a matching model ID/capability or passing connection probe is not Axiom's independently approved expected digest and does not prove which weights executed. Consent gates cannot confine a malicious compiled adapter with ordinary process authority. No general dynamic arbitrary-code plugin facility is established by these sources. Keep Axiom's narrow protocol and fixed adapter allowlist; reject duplicate identities instead of accepting implicit replacement; isolate any later executable adapter with no ambient credentials/files/network authority. [^https://github.com/Kartik24Hulmukh/Axiom-Grid/blob/704fb45fd3c521346b86a4bf66ba68e529191ce6/docs/MODEL_IDENTITY_POLICY.md]

### 3. Credential and cloud boundaries: useful AI-library patterns; ArtCraft-X is a direct blocker

**AI library positives:** `plan` validates request compatibility and adapter availability; `start` checks consent before preparing the provider/key for execution. Consent is scoped by app, connection, destination, capability and data kinds with expiry; local connections require no cloud consent. Default `standard` client uses environment then OS keychain and enables job history. A caller can explicitly choose a passphrase-encrypted fallback (Argon2id + XChaCha20-Poly1305); this is **not** the default plaintext fallback. Layered-store errors may fall through to another successful layer, so fallback policy and visibility need review. [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-client/src/client.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-core/src/consent.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-native/src/secrets/keychain.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-native/src/secrets/file.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-native/src/secrets/crypto.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-native/src/secrets/layered.rs]

**ArtCraft-X concrete blocker:** CredentialToml serializes cookie/API-key credentials and writes TOML directly with `std::fs::write`. The credential-list IPC returns a payload containing the **full API key**, not just its display prefix. The main window has HTTP fetch permission for `https://*` plus localhost:12345, download/upload plugin permissions, and native credential commands. This increases the consequences of a renderer compromise; it is not proof such a compromise or exfiltration occurred. Never reuse this credential UI/storage pattern for Axiom. [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/crates/artcraftx/src/credentials/credential_toml.rs#L62-L85] [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/crates/artcraftx/src/commands/credentials/credential_payload.rs] [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/crates/artcraftx/src/commands/credentials/list_credentials_command.rs] [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/crates/artcraftx/capabilities/default.json] [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/crates/artcraftx/src/lib.rs]

**Mitigation:** keep Axiom preview cloud-free/key-free; if cloud is ever separately authorized, provision scoped credentials outside the renderer, return only opaque IDs/redacted metadata, use per-app OS-protected storage, explicit per-request destination/payload approval and deletion/retention controls. Shared suite stores and a generic keychain service name are not a tenant/security isolation boundary. Default history also requires a deliberate retention decision. [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-client/src/client.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-native/src/secrets/keychain.rs]

### 4. Local ≠ offline; global input and shell must stay absent

**Observed:** AI endpoint parsing treats literal loopback as local and allows plain HTTP only there. AI HTTP disables proxies for loopback but supports hosted environment proxies; model downloads have explicit per-hop host checks and auth-host token scoping. These are worthwhile transport patterns, but a local backend can itself use cloud services, and setup/downloads are network operations. No disconnected complete-stack acceptance was performed. [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-core/src/endpoint.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-http/src/lib.rs] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/crates/ai-comfy-env/src/download/transport.rs] [^https://github.com/Kartik24Hulmukh/Axiom-Grid/blob/704fb45fd3c521346b86a4bf66ba68e529191ce6/docs/AUTHORIZED_PREVIEW.md]

**Global-input evidence:** the sampled ArtCraft-X main capability/manifests and app initialization do **not** show a global-shortcut/keyboard-hook/auto-type plugin grant. Do not invent a keylogger finding. They do show HTTP/opener/dialog/upload authority; frontend hotkey enums alone are not OS-wide capture. The launcher intentionally has process-launch/install authority. This was a targeted sample, not an exhaustive proof that every native path/transitive crate lacks input capture or shell invocation. [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/crates/artcraftx/capabilities/default.json] [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/crates/artcraftx/src/lib.rs] [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/crates/native/src/install.rs]

**Mitigation:** preserve Axiom's visible explicit input/manual copy; do not add accessibility, screen capture, clipboard read, global input hooks, shell execution, or update actions to its preview allowlist. Separately qualify disconnected cold starts, missing assets, backend egress, focus/Unicode manual-copy behavior, cancellation and quit; loopback alone is insufficient. [^https://github.com/Kartik24Hulmukh/Axiom-Grid/blob/704fb45fd3c521346b86a4bf66ba68e529191ce6/docs/AUTHORIZED_PREVIEW.md]

### 5. Shared-library/API/fork/license coupling blocks “just add the crates”

The three Craft libraries/workspaces carry actual MIT and Apache-2.0 license texts and dual-license manifest declarations, not merely an API metadata label. That is potentially reusable code, subject to exact component/asset obligations. They are not drop-in Axiom UI replacements: launcher/libs require Rust 1.95, integrations declares 1.90; egui 0.37 family and winit use pinned Storytold forks. Root `[patch]` recipes must be reproduced coherently by a consumer rather than assumed inherited. Integration's own PLATFORM-CONTRACT/CORE-SYNC warns that its local craft-ai-core and craft-libs' copy are not interchangeable: consent-term/model-folder additions and shared-store compatibility remain separate work. A single source/type identity and reviewed migration policy are required. [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/Cargo.toml] [^https://github.com/storytold/craft-libs/blob/b4afa6d22ae41bd36524c32dbcab3ff257ae4cdd/Cargo.toml] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/Cargo.toml] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/docs/PLATFORM-CONTRACT.md] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/docs/CORE-SYNC.md] [^https://github.com/storytold/craft-launcher/blob/deccd0ac1e83313c4e433f49bdfff3b42ba9a716/LICENSE-MIT] [^https://github.com/storytold/craft-libs/blob/b4afa6d22ae41bd36524c32dbcab3ff257ae4cdd/LICENSE-MIT] [^https://github.com/storytold/craft-ai-integrations/blob/60b84aed84a172e2bc7f82fbda4a6ecd4a74d4a9/LICENSE-MIT]

License metadata **null does not mean “no license”** for ArtCraft-X. Its full tree contains vendor HTTP-plugin license texts, and `frontend/package.json` declares MIT. However, no repository-wide LICENSE/COPYING grant was located in the untruncated tree; the desktop crate sets `license = ""`. The frontend declaration and vendor licenses do not establish rights to all original Rust code/assets. Treat scope as unresolved and obtain a component-specific grant before copying; do not assume the separate artcraft repository's license automatically applies. [^https://github.com/storytold/artcraftx/tree/c6b5d338303251d8bcb93ec6806b412f95127936] [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/crates/artcraftx/Cargo.toml] [^https://github.com/storytold/artcraftx/blob/c6b5d338303251d8bcb93ec6806b412f95127936/frontend/package.json]

Transitive scope matters: craft-libs ATTRIBUTION explicitly documents optional embedded hyphenation patterns, including GPL-2.0-or-later Slovak patterns through `hypher/slovak`, potentially enabled by feature unification. Other asset/notice obligations and vendored PDF components exist. This is a **feature-specific review trigger**, not a finding that every craft-libs consumer is GPL. Review the selected feature closure, lockfile, vendored modifications, fonts/media/model terms and distribution notices; root permissive licensing cannot clear the whole graph. No dependency-resolution/build/license scan was run. [^https://github.com/storytold/craft-libs/blob/b4afa6d22ae41bd36524c32dbcab3ff257ae4cdd/ATTRIBUTION.md] [^https://github.com/storytold/craft-libs/blob/b4afa6d22ae41bd36524c32dbcab3ff257ae4cdd/Cargo.toml]

## Premortem → required mitigation

| Failure after integration | Required mitigation before reconsideration |
| --- | --- |
| Compromised release/feed serves matching malicious bytes and hash | Separate pinned authorization root, signed versioned metadata, rollback/freeze defenses; verify package identity per OS before privileged use |
| UI compromise enumerates keys and can reach arbitrary HTTPS | Opaque credential handles; no full secrets over IPC; renderer egress allowlist; keychain/broker boundary |
| “Local” route leaks through backend/cloud/proxy | Network-denied acceptance and egress observation; approved backend config/assets; no hosted fallback in preview |
| Same model ID resolves to another adapter/weights | Immutable qualified identity mapping, duplicate-registration rejection, Axiom preflight/response checks retained; acknowledge reported-only limit |
| Shared-store update changes endpoint/retention or breaks one app | App-owned trust configuration, strict schemas, versioned migrations/backups, explicit endpoint changes and retention policy |
| Cargo update brings fork/API/license drift | Exact commit/lock/feature pins, one coherent core/GUI graph, reviewed SBOM/notices, upstream-delta ownership and rollback |
| Installer helpers or global input quietly expand preview authority | Separate signed installer/updater process; deny capture/typing/shell/clipboard capabilities in preview; platform acceptance gates |

## Recommended next step

Keep this as a reference-design research result. Prioritize three bounded Axiom-owned design notes: (1) artifact authorization versus checksum integrity, (2) explicit consent + opaque credential handles for any future separate cloud product, (3) staged/cancellable lifecycle with no privilege expansion. Any later proposal must name the exact crate, SHA, feature set, legal grant and trust delta, and undergo a separately authorized test plan. No clean-room claim, production readiness, user traction, real-provider success, offline certification, or build compatibility is established by this static review.
