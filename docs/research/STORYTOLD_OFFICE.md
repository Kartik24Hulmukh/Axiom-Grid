# Independent office-suite source review for Axiom-Grid

Review date: 2026-10-28 UTC. Scope: **WordCraft, GridCraft, DeckCraft, PdfCraft only**. Decision: **do not integrate the suite into the authorized preview**. There is real implementation and reusable architecture here, but neither Office/Acrobat parity nor production qualification follows from a feature catalog or a clean-room description.

## Method and evidence boundary

Read-only static review: organization metadata from supplied `org-repos.json`; each `main` resolved once by the supplied helper, one recursive public tree request per repository, then raw files at that SHA. Exactly **12 fetched files per repository**, including README, manifest and two license files; 48 total. Trees were not truncated. No clone, checkout, build, installation, dependency execution, model run, credentials, product write or Git mutation. Only review/cache files outside the product repository were created. The helper's `git ls-remote` was read-only. No runtime or passing CI result was independently observed. Test statements below mean **test code inspected**, not tests passed. Sampling does not establish absence of other features or defects.

## Decision matrix

| Repository | Recommendation | Narrow useful opportunity | Main reason not to integrate now |
|---|---|---|---|
| WordCraft | **Prototype**, isolated research only | Explicitly supplied DOCX bytes → displayed text/structure, no write-back | Lenient/partial fidelity, large parser budgets, model coupling; document access exceeds today's text-only profile |
| GridCraft | **Pattern**; conditional small-module prototype | Pure number-format display for user-supplied values | No demonstrated spreadsheet need; calculation/round-trip behavior is a much bigger contract than formatting |
| DeckCraft | **Defer** product integration; borrow bounded-package pattern | Slide-omission warnings and cumulative inflate-work accounting | Alpha presentation/media stack, partial import, raster-backed PDF, low fit to text preview |
| PdfCraft | **Pattern** now; defer full integration | Separate read/write permissions and fail-closed mutation semantics | Hostile-file hangs/crashes acknowledged, OCR/model rights and language limits, high-stakes redaction/signature surface |

These are reviewer recommendations, not upstream support promises. No candidate warrants immediate production integration.

## Axiom boundary: the gating issue is authority, not language compatibility

Local authoritative inputs inspected: `model-identity-published/docs/AUTHORIZED_PREVIEW.md`, `docs/LICENSE_AUDIT.md`, and the focused README. The preview accepts explicitly supplied text in a visible window, returns a suggestion for review/manual copy, and grants no filesystem, clipboard, screen or shell capability. No automatic insertion, document edits or message sending. Bundling remains disabled, native qualification and parser/OS sandbox work remain open. The local license audit explicitly rejects root-license and clean-room shortcuts. These local documents were read, not changed; SHA-256 anchors are recorded below.

An opt-in office MCP server is **not** equivalent to the Axiom preview's narrower authority: it can open/save documents or operate a desktop app. Do not attach these servers, use remote UI bridges, auto-save generated files, or grant directory access inside the current preview. Even user-selected DOCX/PDF extraction is a separately approved capability expansion, not something already authorized by “explicit input.” Keep any experiment outside the shipping preview; display extracted content as untrusted data, not instructions. The existence of local stdio/loopback control does not prove offline operation, origin authentication, sandboxing or safe multi-user deployment.

## WordCraft — useful DOCX research, not an Office replacement

**Implemented surface.** Public `wordcraft-docx` functions expose read/write, password-aware read, Word XML sniffing/read, encrypted package helpers and DOCX/DOCM/DOTX/DOTM flavors. CLI dispatch exposes conversion, plain text, JSON inspection, rendering, scripted commands and MCP. The lower parser is a library, not necessarily a GUI embed; its manifest still requires the WordCraft document/geometry model plus XML/ZIP/crypto dependencies. Preserving macro-bearing packages must not be mistaken for executing or safely sanitizing macros. [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/crates/docx/src/lib.rs] [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/crates/docx/Cargo.toml] [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/apps/wordcraft-cli/src/main.rs]

**Formats/fidelity.** README/CLI list DOCX, ODT, RTF, HTML, Markdown, LaTeX and TXT, legacy DOC read, PDF/PNG export and XML variants. Only the DOCX API/package and PDF facade were sampled here; other converters were not independently traced. The DOCX reader explicitly skips unknown markup and defaults bad numbers. Package defaults are 256 MiB per part, 512 MiB cumulative, 20,000 entries; actual inflated bytes are charged even after failed reads. These are meaningful controls, not proof against all malformed input, and are far too generous to inherit unquestioningly into a bounded text preview. PDF uses layout/fonts, craft-pdf and Krilla; tagged output is best effort and undecodable images may be replaced/skipped. [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/README.md] [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/apps/wordcraft-cli/src/main.rs] [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/crates/docx/src/lib.rs] [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/crates/docx/src/package.rs] [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/crates/pdf/src/lib.rs]

**Evidence vs aspiration.** MCP tests actually construct headings/bold/table/text through protocol calls, inspect results, render a page and assert headless screenshot refusal; other tests cover line caps and multi-document targeting. This is substantive test intent, not observed UI operation or Office round-trip certification. Upstream calls itself alpha; 97% ribbon/menu command coverage coexists with substantially lower readiness estimates and explicit beta gaps in real DOCX testing, chart/SmartArt round trips, pagination and native printing. Never quote the command percentage as fidelity. [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/crates/mcp/src/tests.rs] [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/README.md]

**Reuse and fit.** MCP Headless calls a real Session; Remote reaches app control, including UI actions. Headless roots default to `None`; `with_automation_roots` supplies confinement. It is not a read-only extractor API. Prefer a future byte-in/text-plus-warnings-out child process over broad CLI/MCP attachment. First experiment, only if separately authorized: a small representative DOCX corpus, no outbound access, no save methods, lower byte/time/memory limits, explicit extraction-loss banner and manual copy only. Do not round-trip a user's original as part of the trial. [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/crates/mcp/src/lib.rs] [^https://github.com/storytold/wordcraft/blob/aadb077e072b7de05f724e359d8db82e151f125c/crates/docx/src/lib.rs]

## GridCraft — strongest small reusable module, conditional on need

**Implemented surface.** `gridcraft-xlsx` provides byte-slice XLSX read with `ReadReport::warnings`, XLSX-family writing, CSV import/export, XLS/XLSB/ODS import and decryption helpers. XLSX writer selects macro-enabled output when VBA is present. Parser depends on core, formula and model crates, not merely a generic ZIP reader. CLI has formula evaluation, workbook scripts, cat/range output and MCP; MCP offers headless sessions and a desktop Remote backend. [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/crates/xlsx/src/lib.rs] [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/crates/xlsx/Cargo.toml] [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/apps/gridcraft-cli/src/main.rs] [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/crates/mcp/src/lib.rs]

**Limits.** README explicitly restricts legacy XLS to values/formulas/number formats, not formatting/objects; XLSB and ODS worksheet imports use saved values rather than formulas. This distinction is essential for analytics: a successfully loaded workbook is not evidence of recalculation correctness. XLSX reader is lenient with warnings capped at 1,000. Package ceilings are 512 MiB per part, 1 GiB total and 200,000 entries, with budget charging on failed reads. No broad “Excel parity” conclusion is supportable from these files. [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/README.md] [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/crates/xlsx/src/lib.rs] [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/crates/xlsx/src/package.rs]

**Test evidence.** Sampled malformed-file tests assert rejection/handling of garbage, missing/invalid workbook parts, huge dimensions, deep/broken XML, ZIP expansion, hostile formula text and repeated column work. These are concrete regressions worth borrowing, but they were not run and do not establish calculation, round-trip, Windows or WASM correctness. [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/crates/xlsx/src/tests/malformed.rs]

**Highest-leverage small code candidate:** `gridcraft-numfmt`, if Axiom develops a validated tabular-text preview use case. Public `NumberFormat` parsing/display exposes formatted text, color and date/percentage categorization; its manifest has only `gridcraft-core` as a direct dependency. The interface explicitly says **en-US only**, uses an Excel-style 255-character parse cap and includes date-system semantics. It is lower-coupling than a workbook engine, but it is not a single independent file: builtin/decimal/parse/render modules and core types remain necessary, and no transitive or internal-module audit was performed. Limit raw input bytes as well as parse characters: even overlong codes are retained as strings. Preserve original values alongside formatted display; never silently imply locale or numeric/date equivalence. This is a conditional prototype, not a present product requirement or a fully vetted extraction. [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/crates/numfmt/Cargo.toml] [^https://github.com/storytold/gridcraft/blob/146161b4b450a56e5e59a083ba0478582d1e602b/crates/numfmt/src/lib.rs]

## DeckCraft — defer; two concrete patterns are worth retaining

**Implemented surface.** `deckcraft-pptx` exposes byte-input import, `import_checked` (returns omitted-slide part names), theme import, PPTX/POTX/PPSX output and encryption detection. It is coupled to presentation/geometry/color types. CLI has rendering, scripted commands, save/export and MCP; MCP is an actual headless/Remote split. No legacy PPT compatibility or encrypted-package decryption was verified from these APIs. [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/crates/pptx/src/lib.rs] [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/crates/pptx/Cargo.toml] [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/apps/deckcraft-cli/src/main.rs] [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/crates/mcp/src/lib.rs]

**Limits and patterns.** Import intentionally skips unknown/bad optional content. Default package limits are 512 MiB per part, 96 MiB XML, 2 GiB kept, 4 GiB cumulative inflate work and 50,000 entries. The separate inflate-work budget accounts for discarded parts: a useful pattern where “kept bytes” alone would miss expensive decompression. Test code explicitly exercises discarded-part charging, XML ceilings and relationship path normalization. `import_checked`'s omission list is preferable to pretending every slide survived, but does not certify shape/media-level fidelity. All ceilings still need much smaller workflow-specific limits and process isolation for Axiom. [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/crates/pptx/src/opc.rs] [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/crates/pptx/src/lib.rs] [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/crates/pptx/src/read.rs]

**Exports and maturity.** PDF implementation renders slide appearance as imagery and overlays invisible text for search/selection, plus links/bookmarks and notes/handout layouts. That is not vector/editable Office fidelity or proof of correct reading order. README calls this alpha and describes breadth-based feature percentages; media/animation/presentation claims were not executed. A text-only preview has no clear reason to take on a presentation renderer plus codec stack now. [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/crates/pdf/src/lib.rs] [^https://github.com/storytold/deckcraft/blob/f893f6af7d36a5409fd804e81a34fd895cfefedf/README.md]

## PdfCraft — useful defensive design, largest high-stakes surface

**Implemented surface.** COS public facade exposes lazy/tolerant object parsing, copy-on-write overlays, encryption, full and incremental writing, decode budgets and a read-only-limit error. Its “standalone” description still entails crypt/filters crates. Export facade provides DOCX, HTML, RTF and PPTX over an intermediate page/block/table/image model; flowing paragraphs and positioned shapes are reconstructions, not recovered original Office structure. Export internals were not sampled. CLI routes info/text/render/edit/combine/extract/split, automation and robustness checks; these are implemented entry points, not a guarantee of all advertised behavior. [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/crates/cos/src/lib.rs] [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/crates/cos/Cargo.toml] [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/crates/export/src/lib.rs] [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/apps/pdfcraft-cli/src/main.rs]

**Concrete limitations.** COS says bounded-memory streaming of very large files and linearized output are not yet implemented. README acknowledges alpha, hostile-file crashes/hangs, no side-by-side quality benchmark, weak existing-text editing especially CJK/RTL, limited Office conversion, signature/online validation gaps and incomplete advanced preflight/XFA. OCR implementation uses ocrs plus separately provisioned models, English/limited alphabet, and a Helvetica/WinAnsi text layer; it is not Hindi/Marathi/general multilingual OCR. The OCR E2E test returns early with a “skipped” diagnostic if models are absent, so even a green suite alone would not prove OCR execution. [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/crates/cos/src/lib.rs] [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/README.md] [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/crates/ocr/src/lib.rs]

**Safety patterns, not security certification.** Automation is a headless mutable Session. Independent read/write roots are useful; source expressly states no checks without roots and a check-then-open symlink race remains if another process changes directories. It is an application restriction, not an OS sandbox. Redaction applies on a copy and commits only on success, checks residue, and refuses vertical writing or uncleanable tags/deep objects. This is a valuable fail-closed pattern; it does not demonstrate forensic erasure, safe saving of every revision, sanitization of every embedded object or legal-grade redaction. Do not put redaction, signatures, JS forms, OCR, print or UI control behind Axiom's preview endpoint. [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/crates/automation/src/lib.rs] [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/crates/automation/src/file_access.rs] [^https://github.com/storytold/pdfcraft/blob/7555be3c7ef1d2dc22ae1327791552812603d520/crates/redact/src/lib.rs]

## Portability and dependency cost

All four roots declare Rust **1.95**, edition 2024; browser/native portability is an upstream target, not something this review tested. Whole applications inherit patched egui/winit trees and shared Storytold craft-libs Git dependencies. At these heads Word/Grid/Deck use craft-libs `92d392cff132eaf53e13afff77f38b5c11b73aa0`, while PdfCraft uses `e11f9d9aebea5f6b8e74643c1ea1ed172ba5f545`. “One suite” does not mean one resolved dependency set or a drop-in Axiom workspace dependency. PdfCraft additionally patches hayro-family, lopdf and vello_common via vendor paths. Individual lower crates may avoid much of the GUI surface; root patch tables do not prove every patch is linked in a proposed minimal adapter. No resolved lockfile/SBOM was audited. CLI/library seams reduce scope; they do not establish portability or automatic security. ## Premortems and mitigations — reviewer proposals

| Failure scenario | Prevent / detect | Stop condition |
|---|---|---|
| Feature-percentage marketing becomes a parity promise; user loses content on save | No save-back trial; reference corpus with comments/revisions/tables/charts, RTL/CJK, fonts, macros and malformed cases; show omissions/warnings | Any silent omission or unexplained semantic change blocks wider scope |
| Parser stalls or exhausts desktop memory | Separate low-privilege child; no network; explicit input/output byte ceilings, CPU/wall/RSS budgets; lower parser limits; bounded diagnostic output | Hang/crash/resource breach must return visible failure, not partial success |
| “Opt-in MCP” quietly expands preview authority | Do not register upstream general-purpose MCP/UI bridges; keep preview unchanged; future adapter has only one explicitly approved read function | Any capture, typing, write/send/print/remote-control method reachable is a release blocker |
| Path-root check is treated as a sandbox | Pass already-approved bytes/handles; private staging; OS process isolation; no caller-chosen output path; no external-resource fetch | Reachable network/file path outside approved input or unresolved race blocks file-capability approval |
| Format/locale/date display changes the user's meaning | Retain original raw values, make locale/date-system explicit, compare against reference cases; formatting is not recalculation | Unexplained number/date difference blocks formatter prototype promotion |
| “MIT/Apache suite” includes restricted brand/model/assets | Exact build inventory, attribution and source provenance, remove ArtCraft marks, verify model-specific rights, legal review | Missing or unclear rights/notices means no redistribution |
| Safe-looking PDF redaction leaves recoverable data | Keep out of initial scope; later independently inspect serialized output/revisions/attachments/tags and failed-operation behavior | Any residual sensitive content or unverifiable deletion means refuse success |
| Toolchain/forks force integration churn or native startup fails | Pin every selected dependency; minimal crate path; separate qualification project; clean-host/native/offline tests only after authorization | Unbounded vendoring/toolchain migration or no reproducible minimal artifact means defer |

## Bounded next step, not authorization to execute
